# 데모 데이터 만들기

`R__03_seed_demo_couples.sql`이 만든 **회원 6명**을 데모 커플 3쌍으로 완성하는 방법.

---

## 이 작업을 누가 해야 하나

| 상황 | 할 일 |
|---|---|
| **완성본 시드가 저장소에 있을 때** (평소) | `git pull && ./gradlew flywayMigrate` — **끝.** 아래를 읽을 필요 없다 |
| **완성본 시드를 처음 만드는 사람** (한 번) | 아래 전체 절차 |

한 사람이 **한 번만** 앱에서 입력하고, 그 결과를 덤프해 시드로 만들면 그 뒤로는 아무도 반복하지
않는다. 팀원은 마이그레이션만 돌리면 완성된 3커플을 받는다.

> 현재 상태: `R__03_seed_demo_couples.sql`이 **완성본이다.** 마이그레이션만 돌리면 3커플이
> 궁합점수·리포트·추천까지 갖춰진 상태로 들어온다. 아래 절차는 **데이터를 다시 만들어야 할 때**
> (계산식이나 추천정책이 바뀌어 값이 낡았을 때) 참고한다.

## 완성본에 무엇이 들어 있나

| 커플 | 구성 | 성향차 | 총점 | 추천 슬롯 |
|---|---|---|---:|---|
| 커플2 | 김보람 + 박준서 | DIFF_3 (반대) | **62.00** | 예금·적금·투자·대출 |
| 커플3 | 한서연 + 오태윤 | DIFF_4 (최대) | **53.00** | 예금·적금·투자 (대출 ❌ 고금리) |

| 커플 | 자산(25) | 부채(20) | 가치관(25) | 목표(20) | 절세(10) |
|---|---:|---:|---:|---:|---:|

가치관만 24.00으로 거의 만점이다.

## 왜 앱에서 직접 입력하나

설문 결과를 SQL로 직접 적으면 **투자성향이 어긋난다.** `member.investment_type`은 사람이 정하는
값이 아니라 개인설문을 저장할 때 `PersonalInvestmentTypeCalculator`가 나이·소득·자산비중·투자경험
·이해도·원금보존태도·목표·기간으로 계산해 채우는 값이다. 손으로 적은 값이 계산 결과와 다르면
추천·궁합점수가 시드와 어긋나고, 그 시드는 더 이상 정답지 구실을 못 한다.

궁합점수·리포트·추천도 마찬가지다. 전부 앱이 계산하게 두고, 우리는 **입력만** 넣는다.

## 0. 준비

```bash
docker compose up -d
cd backend && ./gradlew flywayMigrate
```

KB스타적금Ⅲ 가입 자격은 회원가입에서 입력받지 않는 값이라 시드가 직접 넣는다. 시드로 만든 회원은
이미 들어가 있고, **앱에서 새로 가입한 계정에만** 아래가 필요하다.

```bash
docker exec -i finance-match-mysql mysql -uroot -proot finance_match \
  -e "UPDATE member SET kb_star_savings_eligible = 1 WHERE email = '<이메일>';"
```

## 3. 앱에서 하는 순서

커플 한 쌍당 아래를 반복한다. **공동설문이 개인설문보다 먼저**여야 한다 — 개인 투자성향 계산에
공동설문의 목표·기간이 들어가기 때문이다. 순서를 바꾸면 `COMMON_SURVEY_NOT_FOUND`가 난다.

```
1. 초대자 로그인 → 자산 연동
2. 초대자 공동설문 작성 → 초대코드 발급
3. 피초대자 로그인 → 자산 연동 → 초대코드 입력 → 커플 연결
4. 초대자 개인설문
5. 피초대자 개인설문   ← 이 순간 궁합점수·리포트가 자동 생성된다
6. 추천 화면 진입      ← 추천 상품이 자동 생성된다
```

## 4. 이렇게 나오면 성공

세 커플이 서로 다른 화면을 봐야 한다.

| | 커플1 | 커플2 | 커플3 |
|---|---|---|---|
| 예금 | ✅ | ❌ 꺼짐 (입출금 합 210만) | ✅ |
| 적금 | ✅ KB스타적금Ⅲ 1등 | ✅ 착한 e-plus 1등 | ✅ KB스타적금Ⅲ 1등 |
| 투자 | ✅ | ❌ 꺼짐 (1개월 내 대출) | ✅ |
| 대출 | ✅ | ✅ 신혼부부 전세 1등 | ❌ 꺼짐 (고금리 부채) |
| 개인 투자 | ✅ 박준서만 | ❌ 꺼짐 (성향 동일) | ✅ 오태윤만 · TDF 1등 |
| 개인 절세 | 김보람 ISA / 박준서 연금저축 | 둘 다 ISA | 한서연 ISA / 오태윤 연금→IRP→ISA |

투자성향은 위에 적은 대로 나와야 한다. 다르게 나오면 개인설문 입력값을 다시 확인할 것.

## 5. 다 만들었으면 시드로 굳힌다

여기가 **팀원이 이 작업을 반복하지 않게 되는 지점**이다. 완성된 DB 상태를 덤프해서
`R__03_seed_demo_couples.sql`을 통째로 교체하면, 그 뒤로는 `flywayMigrate` 한 번이면 3커플이
완성 상태로 복원된다.

덤프에는 회원 3~8번의 것만 담아야 한다(기존 데모 커플 1·2번은 `R__02`가 관리한다). 테이블마다
골라내는 조건이 달라서, 실제 데이터가 만들어진 뒤에 스크립트를 만든다.

그렇게 만든 시드는 손으로 적은 값이 아니라 **계산기와 추천정책이 실제로 내놓은 결과**라, 회귀
테스트의 기준값으로 그대로 쓸 수 있다.

## 조합을 바꾸고 싶을 때

자산은 사람(이메일)에 붙어 있고 커플 짝은 초대코드로 정해지므로, 아무나 짝지어도 된다.
`한서연 + 박준서`처럼 섞으면 같은 사람인데 결과가 달라지는 걸 보여줄 수 있다.

한 사람은 동시에 한 커플에만 속할 수 있으니, 조합을 바꾸려면 먼저 커플 연결을 끊는다.
연결을 끊으면 궁합점수·리포트·추천·공동설문은 지워지지만 **자산과 개인설문은 남는다.**
짝이 바뀌면 공동설문의 목표·기간이 달라지므로 **개인설문은 두 사람 다 다시 제출**해야
투자성향이 새 기준으로 다시 계산된다.
